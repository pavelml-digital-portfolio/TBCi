# Index Strategy Lab (frontend 0.6.1)

`/app/strategy-lab/?index=<catalog id>` opens an index-specific strategy and risk workspace. Explore indices, Overview menus and Wallet index details link to it. The canonical CAB-03/CAB-08 header places the selected index name and a `‹ Choice index` catalog link beside the page title. Choosing another index opens its lab without changing holdings.

Both strategy value and drawdown charts use Lightweight Charts in the shared `TradingChart.tsx` module, with the existing bounded pan/zoom behavior, area/line modes, crosshair values and PNG/CSV exports.

The research engine uses the existing deterministic generated 2018 component OHLCV series from `market.ts`, not a downloaded exchange backtest. Current basket weights are normalized by `indexBasket`; the active 50 index currently maps to the supported 20-asset catalog, and the lab displays that actual calculation count. The page labels the results research estimates, describes current-weight assumptions and excludes slippage, taxes and constituent changes. No new payment, custody or KYC integration is introduced.

Accounting uses the first selected close as the entry price, allocates after entry commission, marks each component daily, and rebalances every 7, 30 or 90 elapsed days (or holds). Turnover includes purchases and sales. A fixed-point solution reconciles target holdings after commission. Final liquidation commission is charged once. BTC uses the same entry and liquidation costs. Drawdowns include initial capital as the initial peak; volatility is the population standard deviation of daily net returns, annualized with sqrt(365).

Risk uses normalized target weights: HHI, effective asset count, largest/top-three exposure and Pearson correlations of component daily returns over the selected period. Liquidity is a capacity estimate based on trailing 30-day generated volume × price and 1% participation, not a live order-book execution quote. Stress losses use the final portfolio value allocated at target weights, with a 0–100% shock to all or one component.

The local account model, persistence keys, saved balances and operation processing are retained. Product copy changes do not add external integrations. FAQ remains ten substantive questions.

Social cards are committed PNG files generated by `tools/generate-social.mjs` from built metadata. Run `npm run build`, then the generator with Chromium, then rebuild after adding pages or changing card titles. Search engines remain blocked by the wildcard robots rule, HTML noindex and Apache headers; explicitly named social crawlers can fetch HTML and images. Actual Telegram cache refresh is outside this repository.
