# Публикация на tbci.pavelml.ru

Актуальная инструкция: [DEPLOY.md](../../DEPLOY.md).

Используется существующий механизм Masterhost VPS: Apache,
`vps-deploy@87.242.65.97:22`, `/usr/local/bin/vps-release`.
DocumentRoot: `/srv/sites/tbci.pavelml.ru/www` → `current/www`.
Отдельный сертификат Let's Encrypt `tbci-portfolio` продлевается автоматически.

Workflow **Publish TBCi** запускается на `push` в `main` и вручную.
Перед выкладкой вызывает общий CI: TypeScript/Astro, production-сборка,
13 браузерных сценариев по 21 исходному экрану. Проверенная сборка передаётся как artifact
с обязательным включением скрытого файла `.htaccess`.

Публикация через `deploy/vps-publish.sh` проверяет архив и SHA-256,
переключает текущий выпуск атомарно и оставляет предыдущий для отката.
После публикации отдельный runner выполняет GET-проверку с повторными попытками и проверяет
действительный HTTPS-сертификат, commit и идентификатор выпуска, лендинг,
кабинет, кошельки, настройки, noindex, robots.txt и неизвестный маршрут 404.
Предыдущий выпуск восстанавливается при подтверждённой ошибке содержимого
или HTTP-статуса этого выпуска. Тайм-аут/сетевой сбой оставляет workflow
красным с результатом `inconclusive` и не запускает ложный откат.

Нужен единственный Repository secret `VPS_DEPLOY_SSH_KEY` с прежним общим
ключом. Адрес и пользователь заданы в скрипте. Публичный ключ сервера
закреплён в `deploy/vps-known-hosts`, дополнительная Variable не нужна.

Все страницы поддомена закрыты от индексации: мета-тег, Apache
`X-Robots-Tag` и постоянный `/robots.txt`. Счётчиков аналитики нет.
Приложение статическое, демонстрационные операции меняют только
localStorage; Node.js на VPS и серверная база ему не нужны.

Для административной проверки использовать `tbci-verify` в workflow
`vps-migration.yml` репозитория `digital-portfolio`. Сетевая недоступность
SSH или HTTPS не подтверждает успешную выкладку: точный статус нужно
смотреть по результатам **Publish TBCi** и публичному `deployment.json`.
